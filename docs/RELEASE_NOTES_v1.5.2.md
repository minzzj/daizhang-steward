# v1.5.2 发布说明 / Release Notes — 对话呈现修整（思考过程折叠 + 最终结果可见 + 审批闭环）

> 发布日期：2026-10-31 · 版本：v1.5.2 · 基线：v1.5.1

## 1. 这次解决了什么

用户反馈（原话）："你该让用户看到只有他自己输入的内容，以及输出的一个思考过程和一个输出的最终结果啊，思考过程展开之后才是各种的详细的内容。"

v1.5.2 把 `/chat` 从"事件流平铺"改成真正的对话结构：

```
你：把最新报告给我看
助手：
  ▸ 思考过程 · 3 步 · 工具 1（点击展开）     ← 默认收起；展开才看到工具调用/查询结果/数据/记忆
  ✅ 最终结果
  找到 4 份报告，最新的是「步骤 4 · reviewer 报告」…
  [交付物卡片：报告/产物，可直接展开/下载]
  [审批卡片：始终可见，点批准/驳回]           ← 不能折叠、不会被藏起来
```

## 2. 新增/修复

### 2.1 消息分相（默认只显示你输入 + 思考过程 + 最终结果）
- `ChatPart` 新增 `phase: "thinking" | "result"`；`ChatMessage` 新增 `result_text` / `thinking_summary`（旧消息自动分类，历史记录也按新样式渲染）。
- 前端/服务端统一分组：思考过程折叠块（标题带 步数/工具/产物/报告 计数），最终结果区可见；交付物（报告/产物）显示在结果区（最多 3 个，其余收起在思考过程）；审批/错误始终可见。
- 思考块内不再嵌套"思考过程"二级折叠（直接平铺思考文本）。
- 工具调用与工具结果合并为**一张卡**（调用中 → 完成/失败 + 耗时 + 结果预览），不再出现永远"调用中…"的卡片。
- 查询类也会先出现"正在查询系统状态…"等思考行，不再一上来就是工具卡。

### 2.2 审批闭环
- **等待审批不再被当作失败**：`executeGoal` 返回 `pending_approval` 时，对话显示审批卡 + "等待你审批"，Run 保持暂停；批准后继续执行并在对话里推送进展。
- **系统动作审批闭环**：危险动作走 `SystemController.plan → 人工确认 → execute`（一次性 confirmation token），不再伪造 run_id；驳回则取消。策略拒绝的动作明确显示"无法执行"而不是让你去批准。
- 危险动作目标 id 归一化（如"受管程序 demo-app"→`demo-app`），避免误判为未知目标。
- 审批卡去掉固定"演示"标签（只有演示数据才标）。

### 2.3 其它修正
- 用户消息头像/名称为"你"，不再出现"我 我"重复。
- 运行深度链接保留且可见（任务类消息可点"查看完整运行过程与证据 →"）。
- 纯查询不再批量生成"产物/报告"级记忆（减少记忆噪音）；任务仍会记录 run/产物/报告摘要。
- 记忆/数据/工具结果全部收进思考过程，默认视野更干净。
