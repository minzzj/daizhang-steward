# v1.5.4 发布说明 / Release Notes — 点名发送 + 独立智能体上下文

> 发布日期：2026-10-31 · 版本：v1.5.4 · 基线：v1.5.3

## 1. 这次解决了什么

用户反馈：
1. "点名发送发不出去"；
2. "你就不能创建单独智能体系弄吗？这种复杂任务你自己干不好的，会有上下污染漂移。"

v1.5.4 实现**点名发送 + 每个智能体独立上下文**：

### 1.1 点名发送（真的发给指定智能体）
- `/chat` 输入框右侧新增**智能体选择器**：自动调度（推荐）/ 系统总控 / 项目总调度 / 办公执行 / 编码代理 / 客户沟通 / 财务 / 核查复核 / 后台运维 / 线索发现 / 内容创作 / 调研分析。
- 选择后发送，消息自动带上 `@role` 点名；也可以直接在输入框输入：
  - `@operator 写一份周报`
  - `财务：整理这个月账本`
  - `请编码代理修一下这个 bug`
  - `点名核查复核检查这份报告`
- 支持 `@` 英文角色名与中文别名（系统总控/项目总调度/办公执行/编码代理/客户沟通/财务/核查/后台运维/线索/内容/调研）。
- `/agents` 每个智能体卡片新增「点名发任务 →」链接（`/chat?agent=<role>`），打开即预选该智能体。

### 1.2 独立智能体上下文（避免上下污染/漂移）
- 每个被点名智能体在自己的**独立工作区**（系统临时盘）和**独立会话历史**中执行：`.steward/chat/agents/<role>/history.json`（只保留该智能体自己的最近任务/结论，最多 8 条）。
- **总控对话的上下文不会进入该智能体**；该智能体也不把自己的完整对话塞回总控——总控只拿到最终结果/摘要，避免长对话互相污染。
- 项目总调度/系统总控被点名时转项目执行器：由 conductor 拆解计划、派发给专项智能体逐步执行（每步仍独立工作区/证据），适合复杂任务。
- 专项智能体（operator/harness/finance/…）被点名时直接用其角色提示词 + 独立历史执行真实 Harness 任务，产物/报告/工具调用回流对话（思考过程折叠可见）。

### 1.3 验证
- 真实控制台实测：`/chat?agent=operator` 预选办公执行 → 发送任务 → 用户消息显示 `@operator …` → 办公执行在独立上下文中执行（思考 8 步/工具/产物/报告）→ 最终结果"我是办公执行，已收到。"；独立历史文件已生成。
- E2E 新增 `chat-agent-route`：`?agent=` 预选、用户消息携带 `@operator`、工具卡片、最终结果。
